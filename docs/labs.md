# Tixmo Labs

Labs is one shared Railway environment for trying out a feature branch before it merges. It is not production. It holds only made-up test data. It sends no email, takes no payments and has no live vendor connections.

## Rules
- **Test data only.** Never copy production data, customer emails or production secrets into labs. Labs has its own secrets, generated when it was built.
- **No outside traffic.** Leave Stripe, Postmark/SMTP, SendGrid, Twilio, Sentry and AWS/S3 unset. With no mail provider set, the API keeps email in-process and nothing is sent. `SHOWPASS_ADAPTER=fixture` stays set; `live` is refused by the code.
- **One branch at a time.** Labs runs one commit. Deploying a new branch replaces the old one.
- **No auto-deploy.** Labs has no deploy triggers. Pushes to any branch deploy nothing here. Every deploy is a manual, pinned SHA.
- **Never point labs at prod or staging.** `DATABASE_URL` and `REDIS_URL` must be `${{labs-postgres.DATABASE_URL}}` and `${{labs-redis.REDIS_URL}}`, which resolve to `labs-postgres.railway.internal` and `labs-redis.railway.internal`.

## Request a branch
Post in the team channel or ask the PM. Include:
1. The PR number and branch.
2. The commit SHA you want. `guard-and-build` and `local-gates` must be green on it.
3. What you are testing, and for how long (7 days at most per request).
4. Any extra env vars. Name them and say why. Secrets are generated by DevOps, never sent in chat.

## Deploy (DevOps)
Always pass the labs environmentId. Never use `railway redeploy`, `railway up` or a branch trigger.
1. Check CI: `gh pr checks <PR>`. Use the newest commit where `guard-and-build` and `local-gates` both pass.
2. Set `RELEASE` on labs-api to the full SHA, with skipDeploys (`variableCollectionUpsert`, environmentId `810da028…`). `/health` reports `RELEASE`.
3. Deploy labs-api, then labs-dash, with a fresh `serviceInstanceDeployV2(serviceId, environmentId: "810da028-c2b7-4874-a0d4-e95242dc2cb1", commitSha: "<full SHA>")` through `railway api`. `start-api.sh` runs `prisma migrate deploy` on the labs DB.
4. Check: `/health` shows the SHA, `/ready` is 200, the dashboard loads. Post the SHA and URL back to the requester.
5. **Going back to an older SHA:** some migrations can't be undone (for example `20261102183000` drops a unique index). A database reset is not available from this repo, so do not deploy an older SHA that needs one until Daniel approves a database change.

## Reset (DevOps)

A scripted labs reset is not available. This repository has no `ops/` directory and no `labs-reset.sh`. No other script resets the labs database.

Do not delete the labs Postgres volume to clear data. Deleting the volume also deletes its backups. Wiping `labs-postgres`, flushing labs Redis, or recreating `labs@tixmo.co` is not a command in this repo and needs Daniel's approval.

## Data and logins
- The Showpass fixture seed is a separate command, not a labs reset: `SHOWPASS_SEED_ALLOW=sandbox npm --prefix tixmoapi2 run db:seed:showpass`. The seed guard allows a Railway environment named `labs`. See `docs/vendor-import-local.md`.
- `labs@tixmo.co` is not created by anything in this repository. Ask DevOps. The password is never in chat or the repo.
- Test logins use `@labs.invalid` addresses. Passwords are generated fresh and handed over in Railway or the box secrets folder, never in chat or the repo.
- The demo vendor key `sp_demo_valid_key` is a fixture value, not a Showpass key.

## Teardown
- **A tenant (one branch or test org) lasts 7 days.** After that, DevOps asks Daniel before wiping or reseeding labs. There is no reset script in this repo.
- **Labs idle for 14 days** (no deploy and no logins): DevOps proposes teardown to Daniel.
- **Deleting anything needs Daniel's approval.** That covers the services, the volumes, the environment or the custom domains. The order is: remove the custom domains → delete the 4 services in labs → delete the 2 labs volumes (pass the labs environmentId) → delete the `labs` environment → Daniel removes the 4 DNS records at Spaceship.
- Every delete passes environmentId `810da028-c2b7-4874-a0d4-e95242dc2cb1`. A volume or service command without an environmentId can apply to every environment.

## Cost
Labs is usage-billed on the existing Pro plan, with no fixed fee. The usual cost is about $6–8 a month, and about $15 at most. Resource caps: api 1 vCPU / 1 GB, dash 0.25 / 0.25 (it sleeps when idle), Postgres 0.5 / 0.5, Redis 0.25 / 0.25. Don't raise them without a reason.

## Known gaps (SWE)
- Since `df3aa0c`, `robots.txt` (Disallow), the API `X-Robots-Tag: noindex, nofollow` and the labs banner are live. The dash noindex meta is added only by JavaScript, and the dash sends no X-Robots-Tag header.
- `/health.branch` shows `main` for commit deploys, because `RAILWAY_GIT_BRANCH` wins over `APP_LABS_BRANCH`.
- `/health` shows `environment: production` because it reads NODE_ENV. Show `RAILWAY_ENVIRONMENT_NAME` instead.
- Credentialed browser CORS is an exact list (`tixmoapi2/src/config/corsOrigins.ts`). The labs fallback is `https://labs.tixmo.co` and `https://labs-dash-labs.up.railway.app`. It does not include production, staging, or `https://*.tixmo.co`.
